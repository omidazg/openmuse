# ربات بله و تلگرام

با این ربات، هر کاربر می‌تواند در پیام‌رسان بله یا تلگرام با همان دستیار «دستیار جی‌پی‌تی» خودش
گفت‌وگو کند، کار پس‌زمینه بخواهد و وقتی کار تمام شد، همان‌جا خبر بگیرد. هر دو پیام‌رسان با یک
پیاده‌سازی کار می‌کنند؛ بله همان Bot API تلگرام را در نشانی `https://tapi.bale.ai` ارائه می‌دهد.

## ۱. ساختن ربات

### بله

1. در بله با `@botfather` گفت‌وگو را شروع کنید.
2. گزینهٔ ساخت ربات جدید را بزنید (یا `/newbot` را بفرستید)، نام و شناسهٔ ربات را وارد کنید.
3. توکنی که می‌گیرید را فقط در فایل `.env` سرور بگذارید:

```bash
BALE_BOT_TOKEN=<توکن ربات بله>
```

### تلگرام (اختیاری)

1. در تلگرام با `@BotFather` فرمان `/newbot` را بفرستید و توکن بگیرید.
2. `api.telegram.org` از سرورهای داخل ایران معمولاً در دسترس نیست. اگر سرور شما در ایران است،
   یک پراکسی معکوس (reverse proxy) بیرون از ایران بسازید که مسیر را بی‌تغییر به
   `https://api.telegram.org` برساند و نشانی آن را تنظیم کنید:

```bash
TELEGRAM_BOT_TOKEN=<توکن ربات تلگرام>
TELEGRAM_API_BASE=https://tg-proxy.example.com
```

توکن‌ها را هرگز در مخزن کد، تیکت یا پیام نگذارید. اگر توکنی لو رفت، از botfather توکن تازه بگیرید.

## ۲. اجرا

- ربات در سرویس `worker` (همان `worker-entry.js`) با روش long polling (`getUpdates`) اجرا می‌شود
  و وب‌هوک لازم ندارد. در اجرای تک‌فرایندی (بدون `DATABASE_URL`) هم کنار کارگزار کارها در
  همان فرایند API اجرا می‌شود.
- فقط وقتی `BALE_BOT_TOKEN` یا `TELEGRAM_BOT_TOKEN` تنظیم شده باشد روشن می‌شود.
- هر توکن را فقط به یک فرایند بدهید. اگر دو فرایند با یک توکن `getUpdates` کنند، پیام‌رسان خطای
  ۴۰۹ می‌دهد. در `deploy/arvan/compose.yaml` توکن‌ها فقط به سرویس `worker` داده شده‌اند.
- بعد از تغییر `.env`:

```bash
cd deploy/arvan
docker compose up -d worker
docker compose logs -f worker   # باید «messenger bots polling: bale» دیده شود
```

## ۳. اتصال حساب

1. در برنامه به «برنامه‌ها» بروید و «بله و تلگرام» را باز کنید.
2. «دریافت کد اتصال» را بزنید. یک کد شش‌رقمی نشان داده می‌شود که ده دقیقه معتبر است و فقط یک
   بار کار می‌کند.
3. در پیام‌رسان به ربات پیام بدهید: `/link 123456` (ارقام فارسی هم پذیرفته می‌شود).
4. از این پس هر پیام متنی به دستیار همان حساب می‌رسد.

فهرست گفت‌وگوهای متصل و دکمهٔ قطع اتصال در همان بخش برنامه است.

## ۴. فرمان‌های ربات

| فرمان | کار |
| --- | --- |
| `/start` یا `/help` | راهنما |
| `/link <کد>` | اتصال این گفت‌وگو به حساب |
| `/unlink` | قطع اتصال و پاک کردن تاریخچهٔ این گفت‌وگو |
| `/new` | شروع گفت‌وگوی تازه (تاریخچه پاک می‌شود) |
| `/tasks` | فهرست کارهای اخیر و وضعیت آن‌ها |

## ۵. رفتار و محدودیت‌ها

- **فقط گفت‌وگوی خصوصی.** در گروه‌ها ربات پاسخ نمی‌دهد.
- **فقط متن.** پیام صوتی، عکس و فایل فعلاً پشتیبانی نمی‌شود.
- **تاریخچه.** برای هر گفت‌وگو ۲۰ نوبت آخر (۴۰ پیام) در پایگاه‌داده نگه داشته می‌شود.
- **تأییدها فقط در برنامه.** ارسال ایمیل، تغییر تقویم، پر کردن PDF و هر کاری که بررسی یا تأیید
  شما را لازم دارد، در بخش «فعالیت» برنامه انجام می‌شود؛ ربات فقط خبر می‌دهد.
- **اعلان کارهای پس‌زمینه.** هر دقیقه اعلان‌های تازهٔ کارها (انجام شد، ناموفق، نیاز به اطلاعات
  یا تأیید) برای گفت‌وگوهای متصل فرستاده می‌شود؛ هر بار حداکثر پنج اعلان.
- **محدودیت نرخ.** هر گفت‌وگو حداکثر ۸ پیام در دقیقه؛ برای پیام‌های بیشتر فقط یک بار هشدار فرستاده می‌شود. تا سه پیام
  پشت سر هم در صف می‌ماند. پنج تلاش ناموفق `/link` در ده دقیقه، اتصال را موقتاً قفل می‌کند.
- **طول پیام.** پاسخ‌های بلندتر از ۴۰۰۰ نویسه در چند پیام فرستاده می‌شوند. پاسخ‌ها به‌صورت متن
  ساده ارسال می‌شوند و نشانه‌گذاری Markdown حذف می‌شود.
- **سهمیهٔ مصرف.** اگر ماژول سهمیه فعال باشد، پیش از هر پاسخ بررسی می‌شود (قلاب `quota` در
  `apps/server/src/bot/service.ts`).

## ۶. جزئیات فنی

- کد: `apps/server/src/bot/` (کلاینت Bot API، سرویس polling، کدهای اتصال، مسیرهای HTTP).
- مسیرهای API (با نشست کاربر): `POST /api/bot/link-code`، `GET /api/bot/links`،
  `DELETE /api/bot/links/:id`.
- ذخیره‌سازی: اتصال‌ها در owner `system` و kind `bot-links`؛ کدها در `bot-link-codes`؛
  offset هر ربات در `bot-state`؛ تاریخچه در owner خود کاربر و kind `bot-history`.
- پاسخ‌ها از همان دستیار گفت‌وگوی برنامه (`ConversationAgent`) با همان ابزارها ساخته می‌شوند.
